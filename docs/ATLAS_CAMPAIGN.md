# Phase 3 지도 생성 캠페인

## 실행 전 분류

합성 프로젝트 `salt-census`의 승인 상태를 재구성한 `approvedProject()`를 사용한다. 프로젝트 revision은 5이며 내러티브와 시나리오 버전은 각각 1이다. 시나리오의 세 필수 여정과 방앗간 아래 지하 기록실 제약을 모든 사례에 유지한다. 아래 열 개 유형을 각각 여섯 번 실행한다. 성공 여부를 확인하기 전에 분모와 예상 결과를 고정했다.

| 유형 | 추가 조건 | 사전 판단 |
|---|---|---|
| 기본 | 시나리오 조건만 적용 | 가능 |
| 강변 | 수문을 자연 하천에 인접하게 배치 | 가능 |
| 근접 | 의회와 등대 사이 거리 4칸 이내 | 가능 |
| 산지와 항구 | 등대의 산지 선호, 수문을 항구로 지정, 두 장소 간 이동 | 가능 |
| 경계 | 등대는 첫째 지역 안에, 의회는 그 밖에 배치 | 가능 |
| 수로교 | 수문과 등대를 연결하는 인공 수로교와 별도 이동 경로 | 가능 |

입력 번호는 0부터 59까지다. 시드는 `74001 + 97 × 번호`다. 크기, 기후, 육지 비율, 기복, 축척, 정착지·도로·영토 밀도를 바꾼다. 두 번째 Node 프로세스에서는 입력 장소, 시나리오 간선 및 사용자 제약의 순서를 뒤집는다. 두 프로세스가 반환한 World 전체의 직렬화 SHA-256을 비교한다. 가능 사례의 필수 장소, 강제 제약 또는 여정 실패는 캠페인 실패로 집계한다. 불가능 사례의 부적절한 승인도 실패다. 미정 사례는 분리해 보고한다.

## 최종 실행 결과

2026-11-26, 기준 커밋 `116b8ce` 위 Phase 3 작업 트리에서 `atlas-1`을 실행했다. 총 60개 입력 모두 별도 프로세스의 재실행에서 순서를 뒤집어도 World 전체 SHA-256이 일치했다. 출력에는 격자, 정수 고도, 지역 셀, 하천·호수, 영토, 장소 좌표, 조건, 구간 전체 경로와 거리가 포함된다. 원본 프로젝트의 해시는 모든 생성 전후에 같았다.

| 사전 판단 | 입력 | 차단 오류 0건 | 유효 필수 장소 | 충족한 강제 조건 | 가능한 필수 여정 |
|---|---:|---:|---:|---:|---:|
| 가능 | 42 | 42 | 210/210 | 204/204 | 132/132 |
| 불가능 | 12 | 0 | 54/60 | 48/60 | 30/36 |
| 미정 | 6 | 6 | 30/30 | 42/42 | 18/18 |

불가능한 여섯 건은 같은 장소가 같은 지역의 안팎에 있어야 한다는 모순을 진단했다. 나머지 여섯 건은 바다에 고정된 장소와 끊긴 여정을 진단했다. 복합 조건 여섯 건은 첫 실행에서 모두 한 가지 강제 조건을 위반했다. 수문을 먼저 잡고 가까운 양쪽 후보를 검사하도록 조정한 뒤 같은 여섯 입력이 모두 통과했다. 사전 분류는 그대로 유지했다. 첫 실패의 재현 시드는 74874이며, 의회와 등대가 4칸 이내라는 조건이 깨졌다.

### 측정 환경과 범위

- Windows x64, Intel Core i7-12700KF, Node v24.13.0, 설치된 Vite의 SSR 모듈 로더. 순차 실행한 두 프로세스 중 첫 프로세스의 60개 입력을 측정했다. 별도 준비 실행은 하지 않았다.
- `performance.now()`로 공용 `generateAtlas`와 `worldIssues`를 각각 계측했다. Vite 시작, 해시, 파일 출력, 요구별 재검사는 시간에서 제외했다. p50과 p95는 정렬한 60건의 30번째와 57번째 값이다. 화면 그리기와 사용자 입력 지연은 이 측정 범위 밖이다.
- 지도는 48×32 또는 72×48, 장소 5–11개, 경로 3–21개다. UTF-8 JSON World 크기는 15,459–48,328바이트다. 네트워크 및 모델 호출은 0회다.
- 필수 장소는 기존 4곳과 시나리오 선언 1곳을 ID로 검사했다. 각 강제 조건은 실제 `spatialIssues`로 개별 평가했고, 여정은 유효한 물리 경로만 이어서 검사했다. 생성 실패 예측, 인간의 지리적 개연성 평가, 라이브 내러티브 생성 성능에는 이 결과를 일반화할 수 없다.

### 재현

루트 PowerShell에서 아래 명령을 실행한다. `.scratch`는 Git이 무시하는 로컬 디렉터리다. 비교기는 60개 입력의 양방향 SHA-256 전체와 사전 예상 결과를 검사하고, 불일치하면 종료 코드 1을 반환한다.

```powershell
New-Item -ItemType Directory -Force .scratch | Out-Null
node frontend/scripts/atlas-campaign.mjs forward | Set-Content -Encoding utf8 .scratch/atlas-forward.json
node frontend/scripts/atlas-campaign.mjs reverse | Set-Content -Encoding utf8 .scratch/atlas-reverse.json

```

## 한국어 3장 시나리오의 실제 로컬 HTTP 왕복

Phase 2.3의 합성 한국어 배급·증언 시나리오에 문서고 아래 비상 물창고와 두 장소 사이 이동을 추가했다. 입력은 3개 장, 13개 노드, 14개 간선, 퀘스트 3개, 결말 3개다. Python 모의 응답 1회로 만든 설계를 승인 상태로 고정한 후 Vite에서 실제 생성·검사·승인·JSON 가져오기 함수를 실행했다. 실제 사용자 파일과 유료 호출은 사용하지 않았다.

시드 74001의 섬 지도에는 장소 10곳, 경로 9개, 시나리오가 정의한 장소의 배치 2개가 있다. 해로·터널·교량·산길·도로가 포함된다. JSON 내보내기는 237,808바이트였고, 가져온 프로젝트와 승인 시점 프로젝트의 직렬화 SHA-256은 모두 `657e7e7dfcd03fb624855f08aa12b9bec25316b1294deed402ef8f73ef60c9b4`였다. 시나리오와 확정 사실 원본도 같았다. Python `ProjectSnapshot` 검사를 통과한 뒤 임시 포트의 127.0.0.1 모의 FastAPI 서버에 전송했다.

| 제출한 데이터 | HTTP | valid | 진행 상태 수 | 도달 결말 수 | 차단 규칙 | 관측 시간(ms) |
|---|---:|---|---:|---:|---|---:|
| 승인 내보내기 | 200 | true | 18 | 3 | 없음 | 146.11 |
| 미등록 ID를 가리키는 배치 | 200 | false | 0 | 0 | project_reference | 148.26 |
| 경로 끝점의 배치 좌표 누락 | 200 | false | 0 | 0 | project_reference | 144.55 |

두 손상본은 프런트엔드 `isProject`, JSON 가져오기 및 Python 모델에서도 거절되었다. HTTP 상태 200은 검사 응답을 받았다는 뜻이며 결과는 본문의 `valid`와 차단 규칙으로 판별했다. 각 HTTP 시간은 한 번 관측한 값이다. 종료 시 서버 스레드와 소켓을 닫았고 임시 합성 파일을 정리했다.

루트에서 `.venv/Scripts/python.exe -m backend.tests.test_atlas_integration`으로 전체 왕복을 재현한다. Python 모델 회귀만 실행하려면 `.venv/Scripts/python.exe -m pytest -q backend/tests/test_atlas_integration.py`를 사용한다.
