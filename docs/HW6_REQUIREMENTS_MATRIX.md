# HW6 요구사항 대응표

기준은 현재까지 공지된 항목이다. 공식 과제 명세를 받으면 담당자가 문구와 제출 형식을 대조해 이 표를 갱신한다. 아래의 구현 방식과 단계별 목표는 팀의 설계 선택이다.

| 공지 항목 | WORLDWEAVER에서 확인할 행동 | 계획 단계 | 제출 때 확보할 증거 | Phase 0 상태 |
|---|---|---|---|---|
| Product | 디자이너가 아이디어에서 출발해 분기와 장소를 편집하고 설계 자료를 내보낸다. | 1–5 | 입력부터 재열기·내보내기까지의 사용자 시연, 합격 기준별 결과 | 제품 명세·와이어프레임 작성 |
| TDD 3개 이상 | 후보 수, 필수 소재 보존, 잘못된 응답 처리부터 독립적인 동작을 테스트한다. | 1부터 매 단계 | 실제 RED 실패, 최소 구현 후 GREEN, 리팩터링 회귀 기록 | 테스트 계획 작성 및 개발 스킬 확인, 구현 RED/GREEN 증거 0건 |
| LLM 연동 1회 이상 | 실제 제공자의 구조화된 결과를 파싱하고 정합성을 확인한 뒤 편집 가능한 후보로 변환한다. | 1에서 인터페이스, 6까지 실제 검증 | 승인된 실연동의 모델·일자·결과 및 오류 처리, mock과 분리한 기록 | 제공자와 모델 미정 |
| Agent | 실행기가 지리 생성·검증 도구를 호출하고 근거를 남긴다. 오류가 계속되면 두 번 이내에서 복구를 멈춘다. | 1–4, 6 검증 | 도구 호출 기록, 실패·취소·승인 사례, 재검증 결과 | 상태·도구 계약 설계 |
| DevOps / CI/CD | 테스트와 빌드가 통과한 리비전만 Render에 배포한다. | 6 | GitHub Actions 결과, 실패 차단 사례, 배포·재배포 SHA와 상태 점검 | 파이프라인 설계 |
| GitHub | 저장소에서 변경 이력과 검증 결과를 추적한다. | 승인 후 단계별, 6 종합 | 실제 저장소 주소 및 변경과 CI 실행의 연결 | 로컬 origin 설정 확인, 원격 동작 미검증 |
| 지속가능한 SW 개발 | 동일 입력 지도 재현, 불필요한 재생성 억제, 일반 CI의 mock 사용, 호출·재시도 상한 | 1, 3, 4, 6 | 동일 예시에서 호출 수·토큰·빌드 시간 측정, 선택의 장단점 | 측정 계획 작성 |
| 독창적인 제품 개념 | 사건에서 지도를 찾고 지도에서 퀘스트를 찾아 경로까지 검사한다. | 0에서 정의, 2–5 구현 | 직접 작성한 합성 예시, 양방향 편집 및 이동 불가 사례 시연 | 독자적 설계 가설 수립, 시장 검증 전 |

Phase 0 설계 게이트는 **PASS**다. 개발 스킬 4개의 설치 파일과 현재 Codex 세션 목록을 각각 확인했으며 모두 Git 추적 대상에 포함할 수 있다. 검증 방법과 남은 결정은 [Phase 0 보고서](PHASE_0_REPORT.md)에 기록했다.

제품의 지표는 [제품 명세](PRODUCT_SPEC.md), 실제 개발 증거는 [TDD 기록](TDD_EVIDENCE.md), 단계별 종료 조건은 [로드맵](../PLANS.md)에서 관리한다.
