## 사용 흐름

프로젝트 대시보드에서 프로젝트를 만들고 Content Studio에서 소재를 추가·편집·삭제하거나 필수·선택·제외로 분류한다. 소재 한 개로 시작할 수 있다. 별도의 고정 사실 편집에서 작성자의 설정을 보호한다. mock으로 생성했음을 화면에 표시한다. 세 방향의 갈등과 결말을 비교하고 상세를 열어 선택한다. Narrative Studio에서 출처 후보를 확인하고 이야기 필드를 편집한 뒤 명시적으로 승인한다. IndexedDB에 저장한 프로젝트는 새로고침 뒤 같은 브라우저 프로필과 출처에서 다시 열린다.

사용자가 소재를 삭제할 때 고정 사실이나 후보가 그 ID를 참조하면 정본 계약에 따라 삭제를 차단한다.

## 검증 근거

- 서비스 N1 어설션 3개, N2 4개, N3 6개에서 구현 전 RED를 확인하고 같은 테스트를 GREEN으로 통과했다. N4 시간 초과 및 재시도 어설션 2개도 구현 전 실패를 관찰했다. 실제 명령과 실패 요약은 [TDD 기록](TDD_EVIDENCE.md)에 있다.
- 백엔드 `python -m pytest backend/tests -q --tb=line`에서 32개 통과. 단계별 계약, 반복 실패, 재시도 후 성공, FastAPI 상태 오류, 헬스, 정본 왕복을 포함한다. 코드 검토에서 발견한 중복 후보, 같은 소재의 상반된 처리, 끊어진 장소 경로 참조와 비공개 내용 없이 오류 필드를 표시하는 동작도 회귀 검사에 포함했다. Starlette와 AnyIO의 사용 중단 예정 알림 1개가 있었다.
- 이 세션의 Windows 가상환경 초기화는 Python 임시 폴더의 권한 오류로 실패했다. 고정 버전은 작업 공간 안의 `.scratch/python`에 설치해 `PYTHONPATH`로 Python 검증을 수행했다. 서버는 `127.0.0.1:8000`에서 실행해 헬스 200과 없는 API 경로의 404를 확인했다.
- 프런트엔드 Vitest 2개 파일 8개 통과. 후보 선택·편집의 선행 RED와 후속 GREEN에 더해 취소, 오래된 응답, 교체 거부, 임시 편집 유지, 저장 충돌 및 기존 합성 프로젝트 재열기를 검사했다. 정본 타입 생성 결과 일치 검사와 strict TypeScript 검사, `npm.cmd --prefix frontend run build`도 통과했다. Vite가 HTML, CSS, JavaScript를 생성했다.
- 수동 서사 비교에서 공개와 증언자 보호, 대피와 경로 보전, 중재와 자치라는 서로 다른 결정·결과를 확인했다. mock 템플릿을 읽은 결과다. 스키마와 소재 ID 검사는 실제 서사 반영을 증명하지 않는다.
