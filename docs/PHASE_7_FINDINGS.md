## 제외한 판정

- A-01의 저장 기록 유실과 A-02/A-03의 테스트 준비 상태·실행 시간은 서로 다른 현상이다. 장시간 UI 테스트 결과만으로 제품 결함을 추가하지 않았다. 다른 스튜디오의 유사 경로도 개별 재현이 필요하다.
- Ajv의 선택 기능 사용, 비정상 모델 메시지의 실운영 빈도, 생산 프록시의 가용성 영향, 선언되지 않은 동적 청크의 실제 누락은 확인할 증거가 더 필요하다.
- 정상 공개 SHA와 오너의 서비스 정상 보고는 기존 프로젝트 레코드의 동일성 증거로 집계하지 않았다. 동일 HTTPS origin과 프로필에서 저장 ID·리비전을 비교해야 한다. Render 관리자 이력과 실제 롤백은 별도 증거가 필요하다.

## 7A 당시 RED와 구현 인수 조건

- 테스트는 `frontend/src/verificationWorkspace.test.tsx`의 `preserves both saved checks when scenario validation finishes after a Quick Check`다. 합성 프로젝트를 사용하며 응답 순서를 Promise로 제어한다. Quick Check의 저장과 같은 리비전을 확인한 뒤 시나리오 응답을 풀고, 두 기록이 모두 남는지 읽기 전용으로 다시 확인한다. 기존 테스트와 초 단위 제한은 그대로 둔다.
- 오너가 테스트 전용 RED 커밋을 만든 후, 후속 승인 단계에서 해당 SHA·diff·실패를 재확인한다. GREEN의 인수 조건은 변경되지 않은 설계에서 둘 다 저장되고, 설계가 실제로 바뀐 경우의 기존 오래된 응답 차단이 유지되는 것이다. 구현 범위는 이 저장 경로로 제한한다.
- B-01은 현재 RED 그룹 밖의 우선 보안 항목이다. 나머지 재현 가능한 후보는 각각 검토·테스트·구현의 커밋 게이트를 거친다. 설정 확인만 필요한 DEV-03과 간헐성 관측에는 인위적인 실패 테스트를 붙이지 않는다.
