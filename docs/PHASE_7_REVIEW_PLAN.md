# Phase 7A · 독립 최종 감사 계획

기준은 복구 C `50e2a7c02b9c6b7472440850af2617afffcbbf53`와 `feature/final-agent-review`다. 제품의 저장·승인·검증 계약과 공개 운영의 안전성을 확인한다. 시작점은 [제품 사양](PRODUCT_SPEC.md), [데이터 계약](DATA_SCHEMA.md), [에이전트 워크플로](AGENT_WORKFLOW.md), [테스트 계획](TDD_PLAN.md)이다. 배포 증거는 A 성공, B 통제 실패, C 복구를 따라간다. [A 실행](https://github.com/jllgame00/worldweaver/actions/runs/46019534340) · [B 실행](https://github.com/jllgame00/worldweaver/actions/runs/46102057956) · [C 실행](https://github.com/jllgame00/worldweaver/actions/runs/46104696745)

## 실행

1. 코디네이터는 체크아웃과 임시 실패 테스트 제거 여부를 확인하고 공개 스모크 및 전체 정상 회귀를 기록한다. 기본 Vitest 결과와 부하를 분리한 재실행 결과를 각각 기록한다.
2. 독립 하위 에이전트 세 명은 같은 기준을 읽기 전용으로 검토한다. 각 결과에 경로·줄, 재현, 영향, 수정 및 회귀 테스트 제안, 확신도와 남은 불확실성을 적는다. 합성 프로젝트와 로컬 모의 응답을 사용한다.

   | 에이전트 | 검토 범위 | 독립 보고서 |
   |---|---|---|
   | A | 정본·후보 채택·시나리오·지도·세계관·검증과 수리·IndexedDB·언어 전환·비동기 UI | [제품 정확성](PHASE_7_AGENT_CORRECTNESS.md) |
   | B | 서버 자격증명·공개 모드·외부 응답 경계·요청 예산·프로젝트 입력·개인정보·의존성 | [보안과 LLM 신뢰성](PHASE_7_AGENT_SECURITY.md) |
   | C | 보호된 브랜치·CI·이미지와 배포·동시 실행·롤백·런타임·공개 상태·브라우저 보존 증거 | [DevOps와 배포](PHASE_7_AGENT_DEVOPS.md) |

3. 코디네이터는 원본 독립 보고서를 보관하고, 우선순위 후보를 다시 실행한다. 재현된 결함, 운영 위험, 미검증 가설을 구분하고 중복이나 근거가 부족한 항목의 판정을 남긴다. 시간 제한, 저장 준비, 비동기 화면 전환 실패를 각각 조사한다. [종합 판정](PHASE_7_FINDINGS.md)
4. 우선순위가 가장 높은 재현 가능한 결함 그룹에 기존 진입점을 사용하는 회귀 테스트를 추가한다. 해당 테스트가 수집되어 의도한 단언으로 실패하는지 확인한다. 나머지 후보는 오너가 순서와 범위를 선택할 수 있게 근거와 테스트 제안을 남긴다.

## 오너 게이트

`PHASE_7A_READY_FOR_OWNER_REVIEW`에서 멈춘다. 오너가 테스트 전용 RED 커밋을 만든다. 후속 승인 단계에서 그 SHA와 파일 및 실패를 확인한 뒤 최소 구현과 전체 회귀를 진행한다. 오너의 별도 GREEN 커밋과 두 SHA의 기록을 확인한 뒤 다음 그룹을 연다. [Phase 5부터 적용되는 커밋 게이트](PHASE_5_PLAN.md)

실제 브라우저 프로필의 IndexedDB 기록 보존과 내부 배포 이력은 확보된 관찰 범위로 보고한다. 실서비스 상태 조회는 공개 읽기 경로만 사용한다. 테스트 제한 시간과 CI 설정을 그대로 유지하고, 생산 코드 변경과 외부 쓰기 작업은 오너 검토 이후의 범위다.
