# Phase 2.1 시나리오 생성 신뢰성 검증

자동 검증은 통과했다. 수정 후 ChatKHU에서 시나리오를 끝까지 생성한 실적은 아직 없다. 작업 기준은 `main`의 `9c12143`과 기존에 커밋되지 않은 Phase 2 구현이다. 작업 시작 시 백엔드 회귀 검사는 163개가 통과했다.

## 소유자가 경험한 세 오류

| 현상 | 코드와 로컬 환경에서 확인한 내용 | 남은 불확실성 |
|---|---|---|
| 서버 재시작 후 인증 실패 | 게이트웨이 어댑터는 HTTP 401을 인증 실패로 처리한다. 이번 점검에서 현재 프로세스의 ChatKHU 키와 루트 파일의 키가 달랐다. CLI와 서버 모두 프로세스 값을 우선한다. | 과거 요청에 어느 키가 전달됐고 게이트웨이가 왜 거절했는지는 당시 기록으로 확정할 수 없다. |
| 수동 키 설정 후 미완성 응답 | 기존 Responses 어댑터는 `status=incomplete`의 모든 사유를 같은 오류로 바꾸고 세부 사유를 버렸다. 이제 출력 한도, 콘텐츠 필터, 미상 사유가 구분된다. 시간 초과, 명시적 거절, JSON 해석·출력 계약 실패도 각각 다르게 처리한다. | 과거 응답의 `incomplete_details`와 사용량이 없어 출력 한도 소진, 추론 토큰 수 또는 제공자 제한 여부를 소급 확정할 수 없다. |
| 16,000토큰·180초 설정 후 생성 비활성 | 파일에서 두 값을 확인했다. 출력 16,000은 앱 범위에 포함되며, 기존 시간 제한 상한은 120초다. 180초일 때 오프라인 검사로 비활성 사유를 재현했다. 시간만 120초로 바꾼 자식 프로세스에서 설정 검사가 통과했다. | 설정 검사 통과 이후의 인증과 응답 완성은 실제 계정에서 확인해야 한다. |

`scripts.chatkhu check`와 시작 스크립트는 설정 충돌을 변수 이름으로만 알린다. 오류에는 수정할 변수와 범위가 표시된다. 소유자용 `preflight`는 같은 유효 설정으로 모델 목록 GET 1회만 호출한다. 비밀값과 원본 제공자 응답은 출력하지 않는다. 로컬 개발 포트, 루프백 제한, 저장소 이름과 브라우저 출처 정책은 유지된다. [시작과 계정 확인 절차](../README.md#chatkhu-제공자-설정과-시나리오-생성-확인)

## 표준 3장 시나리오와 요청 예산

승인된 이야기, 소재의 필수·선택·제외 구분, 고정 사실, 인물·세력·장소 식별자와 생성 설정을 한 번 보낸다. 엄격한 전송 스키마에서 장·퀘스트·결말의 반복 문장, 무조건 전이의 빈 규칙, 재참조하지 않는 연결·결말 ID를 줄였다. 서버가 참조를 해석하고 ID를 부여한 뒤 기존 정본 스키마, 분기 검증, 고정 사실과 출처 검사를 수행한다. 생략된 보상은 저장할 때도 생략되고, 명시한 조건·효과·보상은 보존된다. 제안 채택 전까지 저장된 설계는 유지된다.

3장 표준 지시의 목표는 노드 12~16개다. 15개 노드·16개 연결·퀘스트 4개·결말 2개 고정 예제의 공백 없는 UTF-8 JSON을 측정했다. 한국어 예제에는 기존 인명과 지명 일부가 영어로 남아 있다. 토큰 수는 로컬 `o200k_base` 추정치이며 게이트웨이 사용량 영수증과 다를 수 있다.

| 출력 예제 | 기존 → 변경 바이트 | 기존 → 변경 추정 토큰 |
|---|---:|---:|
| 영어 | 12,737 → 8,484 | 3,050 → 2,218 |
| 한국어 | 15,907 → 9,922 | 4,113 → 2,716 |

이 범위에서는 전체 시나리오 1회 요청을 유지했다. 서술 후보와 대상 수정은 기본 출력 한도(기본값 6,000)를 사용한다. 전체 시나리오만 `WORLDWEAVER_SCENARIO_MAX_OUTPUT_TOKENS`로 별도 제한할 수 있고, 미설정 시 기본 한도를 따른다. 첫 표준 3장 확인값은 전체 시나리오 12,000, 120초, 1회다. 앱은 두 출력 설정 모두 128~16,000을 허용한다. ChatKHU 문서는 출력 한도 설정과 구조화 출력을 지원하며 해당 계정·모델 조합의 숫자 상한 또는 실제 소요 크레딧은 확인되지 않았다. 추론 토큰은 출력 예산에 포함될 수 있다. 한도 초과 사유가 반환돼도 보이는 JSON만으로 예산이 소진됐다고 단정할 수 없다. [ChatKHU Responses](https://docs.mindlogic.ai/docs/khu/api-gateway/reference/responses-api) · [Responses 추론 토큰](https://developers.openai.com/api/docs/guides/reasoning?api-mode=responses)

생성 전 화면이 요청 수, 전체 시나리오 출력 한도, 시간 제한을 표시한다. 화면에서 확인한 출력 한도와 서버의 현재 한도가 다르면 새 요청 전 설정을 재확인한다. SDK 재시도와 시나리오 자동 재생성은 없다. 실패 시 제공자가 전달한 숫자 사용량만 기록하고 부분 응답은 폐기한다. 새 요청은 소유자가 시작한다. 타임아웃 등 이미 제출한 호출의 비용을 앱이 회수하거나 확정할 수는 없다.

## 확인 범위

- 전체 pytest 209개 통과. 기존 Starlette/AnyIO 사용 중단 경고 1건이 있다. Vitest 42개 통과. 엄격한 TypeScript와 생성 타입 일치 검사, Vite 프로덕션 빌드 통과.
- 정본 Draft 4 및 생성·수정 전송 스키마 검사, 기존 예시 프로젝트의 무손실 왕복을 확인했다. Phase 2.1에서 정본 저장 포맷이나 IndexedDB 마이그레이션 변경은 없다.
- 실제 루프백 FastAPI와 빌드된 화면을 연결해 mock 생성, 대상 수정, 검증 HTTP 200을 확인했다. jsdom과 모의 IndexedDB에서 제안 채택, 승인, 재열기 후 노드 9개와 고정 사실 보존을 확인했다.
- 별도 루프백 mock 서버와 jsdom으로 기존 Narrative Studio 통합 검사 1개도 통과했다. 편집·승인한 이야기와 원본 소재가 후속 생성 실패 후 보존됐다. `git diff --check`와 새 파일의 행 끝 공백 검사도 통과했다.
- 유료 ChatKHU 생성과 직접 OpenAI 호출은 0회다. 실제 계정 사전 점검과 렌더링된 브라우저에서의 실생성은 소유자 검증 대기다. 더 긴 장면, 추론량, 게이트웨이 시간 제한에 따른 성공률과 크레딧은 이번 결과로 예측할 수 없다. [TDD 기록](TDD_EVIDENCE.md)
