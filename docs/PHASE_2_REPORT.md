# Phase 2 · Scenario Studio 검토 보고서

**구현 게이트 PASS · 소유자 검토 가능.** 승인 서사에서 분기 설계를 생성하고 편집·검증·승인한 뒤 다시 여는 경로가 연결됐다. 실제 렌더링 브라우저 조작과 ChatKHU 시나리오 생성은 PENDING이다.

## 사용할 수 있는 기능

| 작업 | 동작 |
|---|---|
| 생성 | 승인된 현재 서사, 소재의 처리 방침, 고정 사실, 등장인물·세력·장소를 서버에서 읽는다. 분량, 1–4장, 분기, 주/부 퀘스트, 결말 구조와 추가 지시를 받는다. 기존 제공자가 구조화된 응답을 반환하면 서버가 ID를 할당하고 검사를 실행한다. 미리보기에서 수락한 설계만 저장한다. |
| 편집 | 그래프 이동·확대·맞춤·자동 배치와 개별 노드 드래그를 지원한다. 왼쪽에서 장·노드·퀘스트를 필터링하고, 오른쪽에서 노드, 연결, 장, 퀘스트, 조건과 결과를 수정한다. 삭제 전 연관 항목을 확인한다. 개요와 키보드로 편집할 수 있다. 실행 취소·다시 실행은 열린 스튜디오에서 최근 30건을 다룬다. |
| 부분 AI 수정 | 노드 설명, 퀘스트 목표, 장의 요약·플레이 전개를 각각 선택해 한 번 요청한다. 변경 전후 내용을 비교해 수락하거나 거절한다. ID와 나머지 설계는 유지된다. |
| 검증과 승인 | 중복 ID·연결, 잘못된 참조, 장과 퀘스트 소속, 출발점, 막힌 분기, 순환, 상충하는 조건, 퀘스트 선행 상태, 도달할 수 없는 결말을 검사한다. 지적 사항은 관련 항목으로 이동할 수 있다. 검증이 완료된 현재 설계를 사람이 검토하고 승인한다. |
| 변경과 복구 | 상위 서사 변경은 기존 그래프를 오래된 상태로 남긴다. 새 제안과 비교해 교체하거나 변경된 원본을 검토하고 기존 그래프를 초안으로 다시 연결할 수 있다. 수동 편집은 초안으로 전환하고 위치 조정은 서사의 의미와 승인을 보존한다. |
| 저장과 교환 | 기존 worldweaver-v1 IndexedDB 이름, 출처, 저장 충돌 토큰을 유지한다. JSON에 장·퀘스트·조건·배치·상태·장소 요구를 저장한다. 불러온 시나리오는 로컬 검토를 다시 받는다. Markdown에는 개요, 사건, 분기, 결말, 퀘스트, 장소와 열린 지적 사항을 담는다. |

## 데이터와 호출 한도

Draft 4 v1 프로젝트에 선택적인 scenario 메타데이터를 추가했다. 기존 nodes, edges, quests, endings 배열과 basis.scenario, versions.scenario를 재사용한다. Phase 1 파일은 변환 없이 열린다. 새 확장 데이터가 들어간 파일을 예전 앱에서 읽는 역호환은 제공하지 않는다. 노드 위치는 화면 좌표다. 시나리오 장소 제안에는 지도 좌표를 넣지 않는다. [데이터 계약](DATA_SCHEMA.md)

React 19와 SVG로 그래프를 구현해 패키지·잠금 파일 변경은 0건이다. 그래프 라이브러리 검토와 키보드 대안, 유지보수 범위는 [아키텍처](ARCHITECTURE.md)에 기록했다.

생성 한 건의 최대 범위는 4장, 노드 32개, 연결 64개, 퀘스트 24개, 결말 8개, 신규 장소 12개와 지리 요구 24개다. 서버가 설정한 시간·입력 바이트·출력 토큰 한도도 적용된다. 시나리오 생성과 수정은 요청마다 제공자를 최대 한 번 호출한다. 인증·한도·응답 오류는 현재 설계를 보존하며, 다른 제공자로 전환하지 않는다. [에이전트 흐름](AGENT_WORKFLOW.md)

검증기는 방문 선행 조건, 상태 값의 일치, 노드·연결의 상태 대입, 퀘스트 실패·완료를 고려해 최대 2,048개 상태를 탐색한다. 참조 연결은 플레이 진행에서 제외한다. 한도에 도달하면 검증 미완료로 승인을 차단한다. 서사적 설득력, 고정 사실과 문장의 의미 일치, 플레이 중 외부 시스템이 바꾸는 상태, 실제 지형의 이동 가능성은 별도 검토 대상이다.

CLI와 백엔드는 저장소 루트의 UTF-8/BOM .env를 읽으며 빈 값을 포함한 프로세스 환경 변수가 우선한다. 이번 세션의 키 값은 두 출처에서 달랐다. 과거 HTTP 401의 원인은 특정할 수 없다. CLI 401 안내와 다른 작업 디렉터리에서의 직접 실행을 보완했다. 자격 증명 값은 기록하지 않았다. 관찰한 RED/GREEN의 실제 명령, 종료 상태와 이미 통과하던 추가 회귀 검사는 [TDD 기록](TDD_EVIDENCE.md)에 있다.

## 소유자 실검증 순서

1. 기존 서버가 있다면 원래 터미널에서 종료한다. [로컬 실행 절차](../README.md)에 따라 필요한 경우 `scripts/setup.ps1`을 실행한다.
2. 실연동 한 건의 예산을 승인한 뒤 PowerShell에서 `$env:WORLDWEAVER_PROVIDER='chatkhu'`, `$env:CHATKHU_MODEL='gpt-6.2-sol'`, `$env:WORLDWEAVER_LIVE_MAX_ATTEMPTS='1'`을 설정하고 `.\scripts\start-dev.ps1`을 실행한다. 키는 기존 서버 환경에 둔다.
3. 기존 프로젝트를 작성한 **같은 프로필과 주소**에서 Projects 목록의 **잊혀진 달 → Open**을 선택한다. 승인된 실제 서사가 있으면 그대로 사용한다. 승인 전이면 기존 실생성 후보를 선택하고 고정 사실을 검토해 승인한다. 기존 기록을 열 때 샘플 생성 버튼을 누르면 같은 이름의 새 프로젝트가 생긴다.
4. 화면에 ChatKHU Gateway와 gpt-6.2-sol이 표시되는지 확인한다. **Scenario Studio**에서 예를 들어 짧은 분량, 2장, 분기형, 단일 결말을 고르고 **Generate scenario**를 한 번 누른다. 오류가 나면 메시지를 기록하고 기존 서사와 설계가 남아 있는지 확인한다.
5. 제안에서 장·퀘스트·결말을 읽고 **Accept proposal**을 누른다. 노드의 설명과 연결의 선택지 또는 조건을 수정해 저장하고 노드를 옮긴다. 부분 수정 검증에는 별도의 유료 요청 승인이 필요하다. 같은 절차를 mock에서 먼저 시험할 수 있다.
6. **Validate scenario**를 눌러 결말 경로와 지적 사항을 확인한다. 차단 오류를 수정하고 재검증한다. 서사 검토 확인란을 선택하고 **Approve scenario**를 누른다.
7. **Saved locally**를 확인하고 새로고침한다. 목록에서 해당 프로젝트를 다시 열어 승인 상태, 편집한 연결·퀘스트와 배치가 유지되는지 확인한다. JSON과 Markdown을 내려받으면 파일 교환도 확인할 수 있다.

## Phase 3 인수 조건

현재 승인된 서사와 시나리오 버전을 다시 확인한 뒤, Phase 3은 기존 위치와 제안 위치 ID, 노드·퀘스트의 위치 참조, travel 필수 연결과 지리 제약을 직접 읽을 수 있다. 두 정착지 사이의 지형은 geography.via로 식별한다. 지형 배치·경로 생성·실제 이동 검증은 다음 단계의 범위다.

변경은 백엔드 제공자·시나리오 서비스·검증기, 프런트엔드 편집기·프로젝트 경계·테스트, 시작 스크립트와 위 문서에 있다. 브랜치와 HEAD를 유지했고 변경은 미스테이징 상태다. 커밋·푸시·배포는 수행하지 않았다.
