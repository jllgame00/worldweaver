## 제품·아키텍처 결정

- 분기의 결말과 그곳까지 가는 길을 함께 설계한다. 시나리오와 지도를 한 Project에 저장하고 장소 ID로 연결한다. 지도에서 사건을 찾을 때는 노드를 역조회한다. 퀘스트가 별도로 좌표나 장소 사본을 소유하지 않는다.
- 시나리오를 먼저 작성할 때는 장소 이름과 ID를 확보한다. 이후 세계 생성기가 같은 ID에 지형과 좌표를 채운다. 그래프 단계에서 미배치 장소가 있는 상태와 최종 설계 승인 조건을 구분했다.
- 제안한 MVP는 React·TypeScript 편집기와 FastAPI 단일 서비스, 브라우저 IndexedDB, JSON 교환과 Markdown 내보내기로 구성한다. 모델은 서사·지리 요구를 제안하고 버전·시드 기반 엔진이 지형과 경로를 계산한다.
- 런타임 에이전트는 검증·생성 도구를 호출하고 리비전별 실행 기록을 남긴다. 자동 복구는 최대 두 번이다. 중요한 변경은 사용자가 검토하며, 사용자가 고정한 사실은 직접 편집할 때만 바뀐다. 실패 시 기존 설계와 미해결 항목을 보존한다.

## Git 상태와 Phase 1 준비도

로컬 브랜치 `main`은 로컬의 `origin/main` 추적 리비전과 같으며 HEAD는 `59a6d5c`다. 작업 트리에 README 수정 1개와 미추적 파일 19개가 있고 스테이징된 변경은 없다. 종료 검토에서 한국어 README와 제품 설계는 기존 바이트를 보존했다. 의존성 설치, 유료 LLM 호출, 커밋, 푸시, 배포, 제품 코드 작성은 수행하지 않았다.

Phase 1은 별도 승인 후 mock 제공자를 사용하는 서비스 경계의 RED부터 시작할 준비가 되어 있다. [TDD 계획](TDD_PLAN.md)의 권장 순서는 다음과 같다.

1. **N1** · mock이 후보 2개, 3개, 4개를 반환할 때 구조가 올바른 3개 묶음만 기존 후보를 교체한다.
2. **N2** · 재생성 시 필수 소재와 제외 조건을 검증한다. 충돌이 있으면 승인을 차단하고 고정 사실의 ID와 문구를 보존한다. 후보 간 결정과 결과의 차이는 사람이 별도로 검토한다.
3. **N3** · 잘못된 JSON, 미정의 속성, 유효하지 않은 소재 참조를 거부하고 기존 설계 필드를 보존한다.
