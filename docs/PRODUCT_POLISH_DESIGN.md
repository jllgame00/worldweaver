# WORLDWEAVER 제품 편집 화면 설계

게임의 한 분기를 고치던 작가가 관련 장소, 고정 사실, 진행 조건을 살펴본 뒤 쓰던 문장으로 돌아올 수 있어야 한다. Phase 5의 기본 화면은 작업 목록, 넓은 편집 영역, 선택한 대상의 검사기로 구성한다. 5A에서는 현재 동작을 조사하고 아래 상호작용을 명세했다. 구현 순서는 [Phase 5 계획](PHASE_5_PLAN.md)을 따른다.

## 공통 화면과 시각 체계

| 요소 | 설계 기준 | 인수 때 확인할 것 |
|---|---|---|
| 작업 틀 | 상단에 프로젝트명, 현재 스튜디오, 저장 상태. 왼쪽에 흐름별 이동, 가운데에 현재 작업, 오른쪽에 선택 대상의 정보·변경·다음 행동. 프로젝트 전환·백업은 항상 같은 위치. | 장면 → 장소 → 장면으로 돌아올 때 선택과 캔버스 시야가 복구된다. 형제 화면에서도 같은 이름과 상태를 읽는다. |
| 폭과 밀도 | 1280px 이상에서 200px 안팎 탐색, 가변 캔버스, 300–360px 검사기. 900–1279px는 탐색을 접고 검사기 전환을 제공한다. 900px 미만은 본문과 검사기를 별도 패널로 열고 뒤로가기로 문맥 복귀. | 1440×900, 1024×768, 390×844와 200% 확대에서 필수 행동이 도달 가능하다. 페이지의 가로 스크롤 없이 캔버스 안에서 이동한다. |
| 글꼴 | 한국어 본문은 ‘맑은 고딕’, Apple SD Gothic Neo 등 설치된 한글 고딕, 영문은 기존 산세리프. 읽기 전용 작품 제목은 명조/Georgia 계열. 본문 16px·행간 1.65–1.8, 라벨 14px, 화면 제목 22–28px. 기술 ID와 좌표만 고정폭. | 장문은 58–72자 안팎의 읽기 폭, 한국어 단어 단위 줄바꿈과 긴 토큰 강제 줄바꿈. 필수 조작 문구를 말줄임으로 가리지 않는다. |
| 표면·색 | 기존 잉크색 배경 `#191713`, 패널 `#201d19`, 필드 `#181612`, 본문 `#f0e7da`, 보조 `#bfb2a0`. 황동색 `#dca57f`은 선택·주행동, 연녹색은 저장/승인, 주홍은 오류. 양피지 계열은 지도와 그 범례에 사용. | 텍스트·아이콘·형태로도 상태를 구별한다. 본문 목표 대비 4.5:1, 핵심 컨트롤·포커스 3:1. 지도 위 글자에는 배경에 맞는 외곽선을 둔다. 실제 대비 측정은 5E에서 한다. |
| 여백·선·아이콘 | 4/8/12/16/24/32px 간격 체계. 필드 간 12px, 작업 묶음 간 24px. 얇은 경계선, 4–8px 모서리. 저장·잠금·경고·이동은 한 계열의 16–20px 선 아이콘과 이름 사용. | 한 작업 구역에 주행동 하나. 긴 폼은 목적별 섹션, 프로젝트 목록과 근거는 행 중심. 정적 장식이 편집 공간을 차지하지 않는다. |
| 조작·접근성 | 공통 버튼·선택 필드·메시지·검사기 헤더·상태·전후 비교행을 기존 HTML 시맨틱 위에 정리한다. 키보드 포커스 링, 마우스 hover, 선택, 읽기 전용, 사용 불가를 분리한다. 컨트롤 높이 36px 이상, 터치 주요 행동 44px 목표. | Tab 순서가 읽기 순서와 일치한다. Enter/Space로 선택, Escape로 보조 패널 닫기, 복귀 포커스 보존. 이유는 버튼 옆에 보이고 `aria-describedby`로 연결된다. 색·hover 단독 정보 금지. |

공통 저장 문구는 **편집 중 → 저장 중 → 로컬에 저장됨(시간)**이다. 저장 실패면 입력을 유지하고 오류 요약·재시도·미저장 사본 내보내기를 함께 둔다. 충돌이면 마지막 저장본을 다시 열거나 사본을 보존한다. 콘텐츠 상태는 **초안 / 원본 변경됨 / 검토 대기 / 승인됨**으로 분리한다. 저장 완료만으로 설계를 승인하지 않는다. 비동기 작업은 실제 단계·취소 가능 여부·실패한 위치를 알리고 포커스를 훔치지 않는다.

## 1. 프로젝트 대시보드

기존 최근 저장순 목록에 제목, 마지막 편집 시각, 서사·시나리오·지도의 실제 상태, 마지막 진행 가능한 작업을 한 행에 담는다. 진행률 대신 기존 출처 리비전에서 ‘서사 승인됨 · 시나리오 원본 변경됨’처럼 설명한다. 새 프로젝트는 이름 입력 → 생성 → Content Studio로 연결한다. 첫 사용 시에는 빈 목록에서 **새 프로젝트**와 **백업 열기**를 제공한다. 기존 샘플 버튼은 현재 개발 빌드 범위를 따른다.

**가져오기·복구**는 파일 선택 → 크기·스키마·참조 검사 → 대상 이름과 저장 시각 비교 → 선택으로 진행한다. 새 ID는 가져오기, 충돌은 사본 만들기/동일 프로젝트 복원/취소다. 복원은 어느 저장본을 교체할지 표시하고 이전 상태를 함께 보존한다. 재확인 중 다른 탭이 저장하면 차이를 갱신한 후 다시 선택한다. 손상된 파일은 원본 보존 및 호환되는 정본 JSON 선택 방법을 안내한다. 프로젝트 및 미저장 작업의 백업과 거절된 시나리오 진단 파일은 용도·확장 설명을 구분한다.

## 2. Content Studio

‘아이디어 붙여넣기’와 ‘소재 직접 편집’을 같은 수준의 탭으로 둔다. 자유 입력에서는 **원문 / 검토 중인 소재**를 나란히 두고 작은 화면에서는 원문으로 돌아가는 전환을 제공한다. 사용자가 입력한 원문 문자열을 별도 프로젝트별 초안으로 보존한다. 공백·빈 줄·모호한 문장을 보존하고 사용자가 명시적으로 지우거나 넘긴다. 초안 저장이 실패하면 상태와 원문 복사/다운로드를 제공한다. 정본의 소재 목록과 구분해 중복 생성 문맥에 넣지 않는다.

| 방법 | 입력·출력·동의 |
|---|---|
| 직접 편집 | 기존 분류, 필수·선택·제외, 고정 사실 편집을 유지한다. 공급자 설정 없이 편집·저장할 수 있다. |
| 규칙으로 정리 | 알려진 한영 제목/라벨과 `-`/`*` 목록만 분류한다. 예컨대 ‘인물: 해온’, ‘장소’ 아래 ‘- 물시계 광장’은 각각 인물·장소다. 목록 밖 설명은 원문 구간과 함께 검토 대기, 미등록 표제 다음 행은 이전 분류를 물려받지 않는다. 추론으로 분류를 채우지 않는다. |
| AI로 제안 | 동의 전 범위·공급자·호출 상한을 공개한다. 장르, 주제·분위기, 인물, 세력, 생물, 아이템·유물, 장소, 역사 사건, 게임 기제, 희망 결말, 서사 제약을 원문 근거와 함께 제안한다. 기존 UserContent enum을 사용한다. 원문 발췌/위치, 허용된 분류, 크기와 형식을 검증한다. |

원문 근거는 사용자가 검토 중인 입력 문자열에서 **정확히 인용한 문구와 1부터 센 등장 순번**으로 지정한다. 양쪽 모두 왼쪽부터 겹치지 않는 일치를 세고, 빈 인용·없는 순번·다른 초안 버전은 거절한다. 이모지 뒤에 같은 한글 문구가 두 번 나오는 입력으로 서버 검증과 화면 강조가 두 번째 인용을 가리키는지 검사한다. 입력 문자열은 분류 전후에 Unicode 정규화·공백 제거로 바꾸지 않는다.

방법과 관계없이 각 행에서 원문 보기·수정·선택·거절이 가능하다. 마지막 **선택한 소재 추가**에만 정본 저장을 연결한다. 수락 전 취소·불량 응답·리비전 변경 시 기존 소재와 고정 사실을 보존한다. 서버 미설정이나 전송 실패면 오류 요약과 **규칙으로 정리 / 직접 편집**을 제공한다. 실제 사용한 방법과 결과는 분리된 로컬 작업 영수증에 남긴다. 원문은 운영 로그에 담지 않는다.

## 3. Narrative Studio

비교 첫 화면의 고정 행은 **누가 무엇을 선택하는가 / 누가 대가를 치르는가 / 어떻게 끝날 수 있는가 / 필수 소재·사실 근거**다. 세 열은 실제 후보의 문장과 출처를 사용하고 근거가 비면 ‘후보에 제시되지 않음’으로 표시한다. 가로 폭이 작으면 기준 하나와 후보 탭을 선택한다. 긴 본문은 선택한 후보만 장·문단 단위로 읽는다. 별도 모델 요청 없이 차이를 검토할 수 있어야 한다.

오른쪽에 잠긴 사실·현재 선택·승인 근거를 두고 원본 소재로 이동한다. 편집 중에는 저장과 승인을 분리한다. 선택 교체·상위 소재 변경 시 기존/현재 리비전과 재검토할 하위 작업을 밝힌다. 생성 실패면 현재 후보와 입력을 보존하고 원인·가능한 행동·실제 호출 여부를 표시한다. 사용자가 재요청을 선택할 때 비용 조건을 다시 제시한다.

## 4. Scenario Studio

기존 React/SVG, 저장된 노드 위치, 장 밴드와 목록을 유지한다. 자동 배치는 장별 진행 방향과 선택지 레인을 만들고 수동 위치를 덮기 전 미리보기를 제공한다. 전이 라벨은 노드 바운딩 박스와 기존 라벨을 피하도록 경로의 여러 지점을 탐색한다. 자리가 부족하면 선택·포커스한 전이만 전문을 띄운다. 긴 노드 제목은 두 줄까지 쓰고 목록과 검사기에서 전문을 읽는다. 미니맵은 같은 위치에서 현재 시야를 그리며 클릭/키보드 이동과 화면 맞춤을 제공한다.

엔딩 선택은 진행 검사기가 실제 반환한 경로 증거를 강조한다. 여러 경로면 예시 경로임을 밝히고, 증거 없음·탐색 미완료는 명시한다. 참고 연결선, 물리 이동, 진행 전이를 다른 선과 범례로 구분한다. 검사기는 **등장·참조 → 진입 조건 → 발생 결과** 순서로 편집한다. ‘관련 장면’ 선택과 ‘플레이어가 먼저 방문해야 함’ 선택은 설명과 상호작용을 분리한다.

과거 진단본에서 프롤로그가 미래의 퀘스트 장면과 엔딩을 모두 요구해 진입 가능한 상태가 0개였다. 새 설계는 편집 시점에 프롤로그·두 대상의 **이름**과 시작 시 방문 기록이 비어 있음을 보여준다. ‘조건 검토’로 해당 필드에 이동하고 결정적 재검사를 실행한다. 합류/선택 분기의 합법적인 조건을 일괄 제거하거나 경로 탐색 상한 결과를 성공으로 바꾸지 않는다.

## 5. World Atlas

셀 경계에서 해안 외곽선을 도출한 뒤 바다와 육지 경계를 벗어나지 않는 범위에서만 곡선을 다듬는다. 등고 음영·생물군계 기호는 기존 고도와 셀 분류에서 파생한다. 강의 합류/유출 방향, 도로의 허용 셀·양 끝점, 항구와 바닷길, 지하·지상 층은 원래 검증 자료에서 그린다. 평활화 결과가 바다나 허용 회랑을 벗어나면 그 구간은 원래 선으로 표시한다. 정치 경계는 영역 외곽선과 옅은 패턴, 장소는 종류별 모양과 층 표식을 쓴다.

전체 보기에는 주요 지역/정착지, 중간 줌에는 주요 이동로/강 이름, 상세 줌에는 소형 장소와 검사용 셀을 표시한다. 겹치는 라벨은 선택한 장소 → 필수 장소 → 지역 → 기타 순서로 양보한다. 숨긴 이름은 검색·목록에서 선택할 수 있다. 레이어 메뉴를 지형/수계/이동/정치/장소로 묶고 표시 레이어와 일치하는 범례·현재 줌의 km 척도를 둔다. 승인된 지도에서 줌·테마·레이어를 바꿔도 정본 좌표·지형·경로·지문이 같은지 검사하고 SVG 출력도 대조한다.

## 6. World Bible

검색 결과는 이름·종류·소속 또는 장으로 구별한다. 이름이 같은 인물도 자료형과 사용 위치로 고를 수 있다. 선택 후 설명 → 소속/관계 → 사용된 장면·퀘스트·장소 → 관련 소견 순으로 읽는다. 관계 그래프와 키보드 목록은 같은 이웃·필터·선택을 공유하며 제안 관계를 구별한다. 기술 ID·필드 경로는 펼쳐서 복사한다. 원본 편집기로 갔다 돌아오면 검색어·선택·스크롤이 복귀한다. 변경 영향은 직접 사용처, 입증된 간접 의존성, 재검토할 승인 순으로 보여주고 확정 사실 변경에는 별도 동의를 유지한다.

## 7. Verification Agent

범위 선택에는 **빠른 검사 / 선택한 기록 / 전체 세계**와 각 도구·비용 설명을 놓는다. 실행 중인 도구명과 실제 완료·건너뜀·취소 사유를 표시한다. 결과 첫 행은 원인, 영향 레코드 수와 이름, 현재 상태다. 관련 하위 증상은 근거가 있을 때만 접고 원시 필드·값은 세부 정보로 제공한다. ‘구조 검사 완료’, ‘의미 검토 안 함’, ‘판정 보류’를 독립적으로 표시한다.

수리 화면은 원래 값과 새 값, 의존성, 검사 전후, 잃게 될 승인을 같은 행에 놓는다. 목록·검증·수락·거절·복구 다운로드를 키보드로 수행한다. 과거 보고서에는 검사한 스냅샷과 현재 상태를 표시하고 재검사로 연결한다. 의미 검토는 별도 선택으로 모델·발췌·상한·가격 가용 여부를 확인한 뒤 동의한다. 제품 품질 점수나 가상 진행률은 사용하지 않는다.

## 8. 운영과 신뢰성

현재 프로젝트에서 확인 가능한 기록과 관측 기간·최근 확인 시각을 표시한다. 기존 `Project.runs`와 `verificationHistory`에 같은 실행이 나오면 run ID로 한 번만 센다. 실제·mock·결정적 실행을 분리하고, 가져온 파일의 이력은 출처를 밝힌다. 범위가 불완전하면 ‘보관된 기록에서 확인한 값’과 ‘집계할 수 없음’을 사용한다.

| 표시 값 | 계수 단위·증거 |
|---|---|
| LLM 생성 요청 | 발송이 확인된 각 시도 1건. 재시도는 별도 시도, 발송 전 미설정·차단은 0, 전송 여부 불명은 별도. 후보/시나리오/향후 추출과 선택적 의미 검토를 목적별로 나눈다. `calls`만 있는 과거 run은 실행 수준의 확인 가능한 합계만 제공한다. |
| 성공 응답·실패 요청 | 전송별 응답 수신과 전송 오류/시간 초과를 각 사건으로 기록한다. 취소 후 도착 여부를 모르면 미확인. 사용자 수락 횟수와 분리한다. |
| 출력 거절 | 실제 수신한 응답이 형식·참조·도메인 검사를 통과하지 못해 후보가 거절된 경우 응답당 1건. 수신 성공과 중복될 수 있다. 편집자가 정상 제안을 거절한 사건은 별도다. |
| 대체 처리 | 로컬 정리기가 실패/미설정에 대한 대안으로 실제 호출될 때 호출당 1건. 안내 노출은 0. 사용자가 처음부터 수동/로컬을 고른 경우 별도 방법으로 기록한다. 해당 영수증 도입 전 기간은 미집계다. |
| 설정·상태·배포 | `GET /api/generation`의 모드/모델/가용 여부와 `GET /health`의 상태·확인 시각을 표시한다. 모델을 호출해 연결 확인하지 않는다. 실제 배포 SHA/버전은 Phase 6가 제공할 때만 표시한다. 앱 버전이나 로컬 HEAD로 추정하지 않는다. |

향후 시도별 영수증에는 실행/시도 ID, 목적·모드, 결과 코드, 있으면 제공된 사용량과 시각만 둔다. 기존 데이터에 합성 이벤트를 채워 넣지 않는다. HW6 제출 증거는 범위·버전·mock/실제 구분이 보이는 익명 예시를 사용한다.

## 한국어 기본·영어 전환

첫 실행의 인터페이스는 한국어다. 명시적 선택 ko/en을 프로젝트 밖의 개인 설정 키에 저장하고 저장소가 막히면 세션에 유지한다. 루트가 언어를 전달하며 locale을 편집 컴포넌트의 React key로 사용하지 않는다. UI 언어로 `document.documentElement.lang`, 날짜·숫자, 도구 제목과 안내를 갱신한다. 창작 언어는 사용자가 입력한 원문·생성 요청의 별도 관심사다. 언어 설정 변경은 Project 쓰기 또는 provider 호출을 일으키지 않는다.

메시지는 기존 copy 모듈을 기능별 리소스로 이관한다. 영어·한국어가 동일한 타입 키와 자리표시자를 가지도록 검사한다. 오류는 서버의 안정된 code·인자·필드 경로로 현지화하며 번역이 없는 외부 오류는 안전한 일반 안내와 복사 가능한 기술 코드로 표시한다. 사용자의 인명·인용문, 자유 텍스트, 고정 사실, enum·ID·저장된 역사적 근거는 그대로 보존한다. 탐색·폼·버튼·상태·승인 요건·빈 화면·접근성 이름·그래프 종류·지도 범례·도구 소견·설정·운영까지 목록화한다. 두 언어와 표준 Intl로 시작하며 새 번역 라이브러리는 필요하지 않다.

## 5E에서 남길 증거

빈 프로젝트의 수동 입력, 키 없는 자유 입력, 장문 후보 비교, 다중 엔딩 경로, 복잡한 해안/항구, 이름 중복 엔티티, 오래된 보고서, 저장 경쟁을 합성 파일에서 재현한다. 한국어·영어로 폭별 화면과 키보드 경로, 선택 복귀, 실패 뒤 재개, 실제 계산된 대비와 숨겨진 라벨 탐색을 기록한다. 목표치는 설계값이며 지금 측정한 사용자 성과는 아니다.

## 5E 구현 참조

작업 흐름은 고정 탐색 레일, 프로젝트별 편집기, 비교 기준을 선택하는 스토리 후보, 시나리오의 상세 편집과 미니맵, 지도 색인, 검증 근거와 복원 비교로 연결된다. 목록으로 잠시 돌아가거나 표시 언어를 바꿔도 같은 프로젝트의 열린 편집기를 유지한다. 독립 사본에는 가져오기 계약을 적용해 원래 검증 기록을 과거 이력으로 남긴다. [공통 디자인 시스템](DESIGN_SYSTEM.md) · [화면별 검수표](PHASE_5E_ACCEPTANCE.md)

## 5E.1 · 작업 중인 프로젝트를 먼저 열기

소유자가 직접 확인한 화면은 한국어 프로젝트 목록이다. **내 프로젝트 / My projects**를 재방문의 기본 작업면으로 쓰고 **예제 프로젝트 / Example project**는 그 아래 한 줄로 남긴다. 프로젝트가 없는 경우에는 예제의 실제 지도와 제작 흐름을 먼저 보여 준다. 도구명·버튼·제목은 로컬 한글 산세리프를 사용한다. 화면 너비 1024px 이하에서는 레일을 접어 960px 창에서도 본문에 공간을 준다.

저장된 지형, 지도 배치, 원본 변경, 승인 상태는 독립적으로 표시한다. 한글 지도 표지와 그래프 제목은 위치나 원문을 바꾸지 않고 축약한다. 실제 기기에서의 폰트 선택과 폭별 판독성은 [시각 검수표](PHASE_5E_ACCEPTANCE.md)에 기록한다.
